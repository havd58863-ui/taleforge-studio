# هل تحتاج n8n؟ تقييم صريح للخيارين — ومتى يفيدك فعلًا

> الخلاصة أولًا: **n8n لا يضيف جودة إبداعية، ولا يحل مشكلة عندك الآن.** هو يضيف ثلاث
> أشياء فقط: **جدولة** (تشغيل تلقائي أسبوعي)، **إشعارات وإعادة محاولة** عند فشل نموذج
> أو GPU في منتصف الليل، و**بوابة موافقة بشرية** قبل الطباعة. أما «تنظيم سير العمل بدقة
> دون تداخل» فالمشروع يفعله أصلًا عبر العقد + المحرر + القياسات.
>
> **الترتيب الموصى به:** (١) Docker على جهازك أو VPS رخيص ← (٢) تجربة n8n Cloud ١٤ يومًا
> للتعلّم فقط ← (٣) **لا** Kaggle + LocalTunnel.

---

## 1) مقارنة الخيارين على المعايير التي تُهم مصنعك

| المعيار | n8n Cloud (تجربة ١٤ يومًا) | Self-hosted على Kaggle + LocalTunnel |
|---|---|---|
| التكلفة | مجاني ١٤ يومًا ثم يُغلق | مجاني «للأبد» نظريًا |
| **استمرارية سير العمل** | ✅ محفوظ | ❌ **الجلسة تُقتل بعد 12 ساعة** والملفات تُمحى |
| **الوصول من الهاتف** | ✅ رابط ثابت | ⚠️ رابط يتغيّر كل تشغيل (LocalTunnel) |
| **Webhooks تعمل؟** | ✅ | ❌ الرابط يتغيّر → كل Webhook ينكسر |
| **مفاتيح الاعتماد** | مخزّنة عندهم | ❌ **تُمحى مع الجلسة؛ وبمفتاح تشفير جديد تصبح غير قابلة للفك** |
| الأمان | عالٍ (مسؤوليتهم) | ❌ محرّر مكشوف للعالم + فيه Code node = تنفيذ كود |
| الجهد قبل كل جلسة عمل | صفر | ١٠–١٥ دقيقة إعادة تركيب + إعادة استيراد كل شيء |
| انطباق الترخيص | شروط الاشتراك | SUL: مسموح للاستخدام الداخلي ✅ |
| مناسب للإنتاج | لأسبوعين فقط | ❌ لا |

**الحقائق التقنية التي تُحسم الأمر:**

- جلسات Kaggle Notebooks محدودة بـ **12 ساعة** (9 لـ TPU)، ولها حصة GPU أسبوعية [1](https://agentdeals.dev/vendor/kaggle).
- عند نهاية الجلسة **تُفقد الحزم والإعدادات** وتحتاج إعادة تثبيت كاملة [2](https://logicity.in/en/blog/how-to-run-70b-llms-free-using-kaggle-s-hidden-gpu-tier).
- n8n يحتاج **قرصًا دائمًا** لسير العمل وللمفاتيح المشفّرة (`N8N_ENCRYPTION_KEY`)؛ بلا ثبات تفقد كل اعتماد مسجّل.
- n8n Community ليس «مفتوح المصدر» بالمعنى الدقيق، بل **Sustainable Use License**: مجاني لاستخدامك الداخلي والتجاري، وممنوع أن تستضيفه كخدمة للغير [3](https://support.n8n.io/article/can-i-use-your-license-for-my-use-case). **لحالتك (مؤلف واحد يبيع كتبه) هذا مسموح تمامًا.**

**خلاصة عملية:** خيار ٢ ليس «مجانيًا للأبد»، بل «إعادة بناء كل يوم» — وهذا أغلى من ٥ دولارات VPS.

## 2) ما يضيفه n8n فعلًا لمصنع TaleForge

| المهمة | هل n8n مناسب؟ | البديل الحالي في المشروع |
|---|---|---|
| تشغيل أسبوعي: تحديث بيانات السوق → أفضل ٥ أفكار | ✅ ممتاز | `cron` + `scripts/ideate.py` |
| إعادة المحاولة تلقائيًا عند فشل Ollama/ComfyUI | ✅ ممتاز | لا يوجد (تحتاجه فعلًا) |
| إشعار على الهاتف: «المخطوط جاهز، راجعه» | ✅ ممتاز | لا يوجد |
| بوابة موافقة بشرية قبل توليد الـ PDF | ✅ ممتاز | `--llm-review` + قرارك بالتشغيل |
| لوحة تشغيل مرئية لمراحل الكتاب | ✅ جيد | الطرفية + `docs/STORY_PIPELINE.md` |
| حساب درجة السوق / فحص التشبّع | ❌ **تداخل خطير** | `market_research_service` (مصدر واحد للحقيقة) |
| فحص ميزانية الكلمات ومستوى القراءة | ❌ **تداخل خطير** | `editorial_review_service` |
| حساب الكعب والمقاس والـ bleed | ❌ **تداخل خطير** | `page_layout_service` |

**القاعدة الذهبية لمنع التداخل:** n8n **ينادي** ولا **يحكم**.

```
n8n (جدولة + موافقة + إشعار + إعادة محاولة)
        │  HTTP فقط
        ▼
Flask API (app/) ← كل القرارات هنا: السوق، العقد، الكتابة، المحرر، التخطيط، الطباعة
```

إن أعدت كتابة أي فحص داخل عقد n8n، ستحصل على **رقمين مختلفين لنفس الشيء** — وهذا هو التداخل الذي تريد تجنّبه.

## 3) الطريقة الصحيحة (خيار ثالث لم تذكره)

**n8n داخل Docker على جهازك أو VPS بـ ٥ دولارات** — مجاني للاستخدام الداخلي، ثابت، وبلا LocalTunnel.

```yaml
# أضف هذا كملف منفصل: docker-compose.n8n.yml
services:
  n8n:
    image: docker.n8n.io/n8nio/n8n:latest
    restart: unless-stopped
    ports: ["127.0.0.1:5678:5678"]        # محلي فقط — لا تكشفه للإنترنت بلا كلمة سر
    environment:
      - N8N_ENCRYPTION_KEY=${N8N_ENCRYPTION_KEY:?set-a-long-random-key}
      - N8N_HOST=localhost
      - WEBHOOK_URL=http://localhost:5678/
      - GENERIC_TIMEZONE=Africa/Casablanca
      - N8N_BASIC_AUTH_ACTIVE=true
      - N8N_BASIC_AUTH_USER=owner
      - N8N_BASIC_AUTH_PASSWORD=${N8N_PASSWORD:?set-a-strong-password}
    volumes: ["n8n_data:/home/node/.n8n"]

  taleforge:
    build: .
    restart: unless-stopped
    ports: ["127.0.0.1:5000:5000"]
    env_file: [.env]

volumes:
  n8n_data:
```

```bash
docker compose -f docker-compose.n8n.yml up -d   # ثم http://localhost:5000 و http://localhost:5678
```

للوصول من الهاتف بأمان: **Cloudflare Tunnel** أو **Tailscale** بدلًا من LocalTunnel (رابط ثابت + مصادقة).

### سير عمل n8n الأولى (٥ عقد فقط)

1. **Schedule Trigger** — كل أحد ٠٩:٠٠.
2. **HTTP Request** → `POST http://taleforge:5000/api/market/summary`.
3. **HTTP Request** → `POST http://taleforge:5000/api/story/write` (بالفكرة المختارة).
4. **IF** `review.passed == true` → **HTTP Request** → `POST /api/render` (PDF) — وإن لا → إشعار.
5. **Telegram / Email** — «الكتاب جاهز للمراجعة» + رابط الملف.

كل ما في هذه العقد **ينادي** API قائمًا؛ لا منطق مكرّر.

## 4) متى **لا** تستخدم n8n إطلاقًا

- عندك كتاب واحد كل أسبوعين → **`scripts/*.py` + cron** أخفّ وأوضح، ولا صيانة.
- لا تحتاج موافقة طرف ثالث ولا إشعارات ليلية.
- لا يوجد GPU يعمل ٢٤/٧ (أهم سبب لإعادة المحاولة هو انقطاع النموذج).

**التوصية النهائية:** ابدأ الآن بالمشروع كما هو (٦ أوامر)، وأضف n8n **بعد** أن تصبح تصدر كتابًا كاملًا أسبوعيًا وتتعب من المراقبة اليدوية. حينها فقط أضف الـ ٥ عقد أعلاه — وستوفّر وقتًا حقيقيًا بلا أي تداخل.

---

## 5) إن أردت تجربة السحابة أولًا (١٤ يومًا)

- استخدمها **للتعلّم فقط**: لا تضع فيها مفاتيح OpenAI/Replicate ولا مخطوطاتك غير المنشورة.
- سجّل سير العمل كـ JSON في `secure_data/n8n/` (مُستثنى من git) لتستورده لاحقًا على نسختك المحلية.
- لا تبنِ عليه مواعيد نشر؛ بعد ١٤ يومًا ستختفي سير العمل.

---

## 6) ما لا يفعله n8n (حتى لو أردت)

- لا يكتب القصة ولا يحسّن النثر (ذاك عمل `LLM_*` + `editorial_review_service`).
- لا يضمن 300 dpi ولا CMYK (ذاك `print_image_service` + `scripts/preflight.py`).
- لا يرفع إلى KDP/Etsy (لا API عام للأول، والأتمتة تخالف شروط الثاني).
- لا يصلح بديلًا عن Kaggle **للتشغيل GPU**: دور Kaggle الصحيح عندنا هو LLM/ComfyUI، لا استضافة n8n.
