# جودة النشر — ما الذي يجعل المُخرَج «بمستوى دور النشر»

هذا الملف يشرح **بالضبط** ما يفعله المشروع الآن لرفع الجودة، وما يبقى خارج قدرته.
كل بند مذكور هنا مغطّى باختبار في `tests/test_app.py`.

---

## 1) الخطوط (Typography)

| البند | الحالة |
|---|---|
| خطوط حقيقية مدمجة | **Andika** (لاتيني، مصمّم لمتعلّمي القراءة) + **Amiri** (نسخ عربي) — رخصة OFL، مرفقة في `assets/fonts/` |
| تضمين الخط في PDF | نعم — `TTFont` + subsetting تلقائي من ReportLab |
| العربية | تشكيل حقيقي + `python-bidi`، والخط يُختار تلقائيًا (Amiri). **تقطيع الأسطر يتم بالترتيب المنطقي ثم يُشكّل كل سطر على حدة** ثم يُرسم بمحاذاة يمين — لأن عكس النص قبل التقطيع يقلب ترتيب الأسطر (خطأ شائع) |
| ضبط السطور | `justify` (محاذاة من الطرفين) بدل النص المتراص يسارًا |
| تقسيم الكلمات (hyphenation) | `pyphen` عبر ReportLab لكل لغة (en/fr/es/de/it/pt/nl)، ومعطّل للعربية |
| الأرامل (widows) | محاولة تضييق عرض الكتلة حتى 3 مرات لسحب الكلمة الأخيرة |
| تصغير تلقائي | يقلّل الحجم 0.5pt في كل مرة حتى 9pt بدل أن يفيض النص خارج الصفحة |
| الفيض | يُعاد كنص متبقٍّ (`overflow_text`) ليُنقل لصفحة تالية — لا نص يُقصّ بصمت |

الوحدة المسؤولة: `app/services/fonts.py` و`app/services/text_layout_service.py`.

## 2) هندسة الصفحة والطباعة

| البند | القيمة |
|---|---|
| مقاسات trim | 6×9، 7×10، 8×10، 8.5×8.5، 8.5×11، مربع 8، A5، A4 |
| Bleed | 3mm (0.125") على كل جهة، والصفحة تُبنى بالحجم الكامل |
| منطقة آمنة | 12mm (0.5") داخل الـ trim |
| أنواع الصفحات | single / spread (+gutter 6mm) / full_bleed (الصورة تتجاوز خط الـ bleed) |
| علامات القص (crop marks) | تُرسم داخل هامش الـ bleed، وتُفعّل بـ `crop_marks=true` |
| حدود التحقق | `validate()` يحذّر إذا bleed<3mm أو dpi<300 أو خرج النص عن المنطقة الآمنة |
| مقاسات مختلطة | كل صفحة تحمل مقاسها (`setPageSize`) بدل فرض مقاس واحد |

## 3) الغلاف (Wrap cover)

* غلاف كامل: **الغلاف الخلفي + الكعب (spine) + الغلاف الأمامي + bleed**، لا صورة أمامية فقط.
* سُمك الكعب يُحسب من عدد الصفحات ونوع الورق:
  `spine = pages × 0.0572mm` (ورق أبيض) أو `× 0.0635mm` (كريمي).
* مساحة باركود محفوظة **2 × 1.2 إنش** بهامش 0.25 إنش في زاوية الغلاف الخلفي.
* نص الكعب يُمنع تلقائيًا إذا كان عدد الصفحات < 100 أو سُمك الكعب < 3.2mm (شرط KDP).
* تحذيرات صريحة: أقل من 24 صفحة = خطأ، أكثر من 828 = خطأ.

## 4) الصور واللون

| البند | الحالة |
|---|---|
| تحجيم | LANCZOS + **Unsharp Mask** بعد التصغير (يستعيد حِدّة الرسوم الخطية) |
| تدقيق الدقة | `check_print_resolution()` يحسب الـ DPI الفعلي لصفحة 6×9 |
| **CMYK** | `convert_to_cmyk()` — تحويل مُدار عبر ICC إن قدّمت بروفايل المطبعة، وإلا تحويل عام مع تحذير |
| إزالة EXIF | `strip_metadata()` قبل إخراج أي ملف |
| فحص جودة قابل للقياس | `evaluate_image()` يقيس: حِدّة (Laplacian variance)، تباين، إضاءة، قصّ الظلال/الإضاءة العالية، تشبّع، نسبة المساحات الفارغة، والدقة الفعلية |

الحد الأدنى للقبول (`gate`): دقة ≥ 290dpi **و** حِدّة ≥ 60 **و** بلا قصّ إضاءة **و** درجة الطباعة ≥ 85.

**ما لا يُقاس من البكسلات:** تماسك الشخصية بين المشاهد، وصحة التشريح. يُعلَّم كـ `estimated`
ولا يُدّعى أنه مقيس. (هذا يحتاج نموذج تحليل أو مراجعة بشرية.)

## 5) الميتاداتا والملفات

* كل PDF يحمل `Title / Author / Subject / Keywords / Creator / Producer` مضمّنة.
* `metadata.json` + `manifest.json` في كل bundle، مع حجم وعدد الملفات وتاريخ الإنتاج.
* KDP/Etsy: تحقق فعلي (7 كلمات مفتاحية، 24 صفحة، 13 tag، 140 حرفًا، مقاسات trim معتمدة).
* EPUB 3 صالح: `mimetype` غير مضغوط، OPF/nav/chapter، و`dir="rtl"` للعربية.

## 6) ما لا يزال خارج نطاق هذا المستودع (بصراحة)

1. **لا يرسم الصور** — يُنتج الوصف (prompt) ويستقبل الصور ويضعها بدقة، لكن الرسم نفسه يحتاج خدمة خارجية.
2. **لا رفع تلقائي إلى KDP/Etsy** — يُجهّز الحزمة والبيانات والتحقق، والرفع يدوي (أو بربط API لاحقًا).
3. **لا مصادقة/صلاحيات** — لا تعرّض الـ API للإنترنت قبل إضافتها.
4. **رفع 300dpi لا يعني جودة فنية** — الجودة الجمالية تحتاج رسّامًا أو نموذجًا مدرَّبًا (هنا تفيد بيانات Kaggle).
5. **لا تحويل ICC تلقائي** — يجب تمرير بروفايل المطبعة عبر `icc_profile` في `/api/images/cmyk`.

هذه الحدود مذكورة أيضًا في `README.md` و`SECURITY.md`، ولم يُدّعَ أي بند منها كمنجَز.
